# Actividad 081 — integración con administración 082/084/088

El panel `/administracion` sigue protegido por `ProtectedRoute` (`ADMINISTRADOR`) y conserva `PrivateLayout`, Navbar, Sidebar, el diseño de escritorio y los diálogos de `ModalContainer`. Figma devuelve 403 desde este entorno: la estructura visual procede de las referencias Tailwind proporcionadas y los colores/tipografías existentes.

El contrato autoritativo está en [`backend/INTEGRACION_ADMIN_082_084_088.md`](../backend/INTEGRACION_ADMIN_082_084_088.md), junto a los DTO reales bajo `backend/src/main/java/com/insectopia/dtos/admin/`. `frontend/src/services/adminService.js` sólo solicita `/api/admin/**` para operaciones administrativas. Los formularios reutilizan el catálogo público existente `/api/catalogos/paises` y `/api/catalogos/paises/{codigo}/regiones` para validar ubicaciones; no se usan otros endpoints para gestionar cuentas.

- Resumen global, tabla paginada, búsqueda por nombre/usuario/correo, filtros combinados por rol y estado, ficha detallada y auditoría de cambios de rol paginada consumen respuestas reales. Cada bloque indica carga, error y reintento independiente; no hay datos de ejemplo.
- Alta (`POST`) usa el contrato de `RegisterRequestDTO`, edición (`PUT`) envía sólo campos editables y omite `contrasena` cuando queda vacía. La validación de formulario reutiliza `validacionRegistro` y la normalización de payload de registro. El backend vuelve a validar todo, incluidos correo/usuario únicos y compatibilidad geográfica.
- Rol y estado usan `PATCH` separados. «Eliminar cuenta» usa `DELETE /api/admin/usuarios/{id}` con confirmación irreversible y casilla explícita; elimina la ficha después del 204. «Desactivar» y «Reactivar» usan `PATCH` reversible, no borran registros. Errores 422 del último administrador aparecen en el diálogo; la UI deshabilita cuentas con `protegida` o `cuentaPropia`, sin sustituir las comprobaciones del backend. Tras cualquier éxito se vuelven a consultar resumen, tabla, ficha, roles e historial. `BLOQUEADO` se mantiene sólo para registros previos; ya no es una acción nueva.
- El historial persistente disponible registra **sólo** cambios de rol. No se muestran auditorías ficticias de altas, edición ni cambios de estado.
- Las conversaciones preservadas de cuentas eliminadas se muestran como «Cuenta eliminada» sin alias ni perfil público; el historial queda en modo lectura, sin compositor ni solicitud de envío.

Pruebas (22/11/2026): `npm test` (**288 correctas**), `npm run lint` y `npm run build` correctos. El build avisa del tamaño del bundle principal (>500 kB), sin impedir la compilación. Para probar manualmente, reiniciar el backend actualizado con Flyway V12 y abrir `/administracion` como `ADMINISTRADOR`; `USUARIO` y `MODERADOR` ven «Acceso restringido». No se requiere versión móvil.
